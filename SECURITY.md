# Security Policy

## Supported versions

Security fixes are prioritised for the latest deployed release and the current default branch. Older releases may not receive fixes.

## Reporting a vulnerability

Do not open a public issue for an exploitable vulnerability. Report it privately through the security contact listed in the signed project agreement. If no separate security contact has been supplied, use the private support contact published by the site operator, currently smartstudypro36@gmail.com. Include a concise description, affected page or component, safe reproduction steps, potential impact and practical mitigation.

Do not include passwords, API keys, payment credentials, production database files, student records or other personal data.

We will acknowledge reports as soon as reasonably practicable, investigate, coordinate a fix and agree on disclosure timing with the reporter. Please do not publicly disclose the issue before a fix or coordinated disclosure date.

## Scope and safe testing

Only test systems you own or have explicit permission to assess. Do not access, modify, delete or export real user data; disrupt availability; conduct social engineering; or perform destructive testing against production services.
